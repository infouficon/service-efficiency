# คู่มือแบบทดสอบการใช้งานระบบฉบับสมบูรณ์ (Comprehensive Manual Test Script — Multi-Role Journey)

เอกสารฉบับนี้ใช้สำหรับทดสอบการทำงานของระบบ **Service Efficiency System (SES)** ครอบคลุมทั้ง 3 บทบาทหลักหน้าร้าน ได้แก่ **พนักงานขาย (Staff)**, **พนักงานคลังสินค้า (Stock)**, และ **พนักงานแคชเชียร์ (Cashier)** พร้อมชุดการทดสอบจำลองร้านค้าจริงแบบ End-to-End เพื่อใช้ในการตรวจรับงาน (UAT) และตรวจสอบความถูกต้องของฟังก์ชันและการจับเวลา Server Timestamps

---

## 1. การเตรียมสภาพแวดล้อมและข้อมูลทดสอบ (Test Environment & Prerequisites)

### 1.1 บัญชีผู้ใช้สำหรับทดสอบ (Test Accounts)
เตรียมบัญชีผู้ใช้ในสาขาเดียวกัน เช่น สาขา **"B01 - Central World"**:
1. **พนักงานขาย (Staff):** Username `STAFF01` / Password ตามที่กำหนด (Role: `STAFF`)
2. **พนักงานคลังสินค้า (Stock):** Username `STOCK01` / Password ตามที่กำหนด (Role: `STOCK`)
3. **พนักงานแคชเชียร์ (Cashier):** Username `CASHIER01` / Password ตามที่กำหนด (Role: `CASHIER`)

### 1.2 การจัดเตรียมข้อมูลสต็อกสินค้าตัวอย่าง (Branch Inventory Setup)
ตรวจสอบในระบบให้มีข้อมูลสินค้าในสาขาทดสอบ ดังนี้:
* **สินค้าที่มีสต็อกพร้อมขาย (`stock > 0`):**
  * iPhone 15 Pro Max 256GB Natural Titanium (สต็อก 5 เครื่อง)
  * iPhone 15 Pro 128GB Black Titanium (สต็อก 3 เครื่อง)
  * AirPods Pro 2 (สต็อก 10 ชิ้น)
  * Silicone Case with MagSafe (สต็อก 4 ชิ้น)
* **สินค้าที่สต็อกหมด (`stock = 0`):**
  * iPhone 15 Pro Max 512GB Blue Titanium (สต็อก 0 เครื่อง — แสดงป้าย "สินค้าหมด")
* **สินค้าที่ปิดการขาย (`active = false`):** ถูกซ่อนจากหน้าจอหน้าร้าน

### 1.3 คำแนะนำการทดสอบจำลองสถานการณ์จริง 3 หน้าต่าง (Multi-Window Simulation)
* **หน้าต่างที่ 1 (Browser ปกติ):** เข้าสู่ระบบด้วยบัญชี `STAFF01` (หน้าจอพนักงานขาย)
* **หน้าต่างที่ 2 (Incognito Window):** เข้าสู่ระบบด้วยบัญชี `STOCK01` (หน้าจอแผนกคลัง)
* **หน้าต่างที่ 3 (Second Profile / Second Browser เช่น Edge/Firefox):** เข้าสู่ระบบด้วยบัญชี `CASHIER01` (หน้าจอแคชเชียร์)

## Part 4: ชุดการทดสอบจำลองร้านค้าจริง 3 บทบาท (Multi-Role End-to-End Simulation)

### TC-E2E-01: Happy Path Full Cycle (ทดสอบกระบวนการสมบูรณ์ 3 บทบาท)
* **เครื่องมือ:** เปิด 3 หน้าต่างพร้อมกัน (`STAFF01`, `STOCK01`, `CASHIER01`)
* **ขั้นตอนการทดสอบ:**
  1. `[STAFF]` รับลูกค้า Walk-in -> เริ่ม DEMO -> จบ DEMO -> เลือก BUY
  2. `[STAFF]` กรอกเบอร์โทร `0812345678` -> เลือก iPhone 15 Pro Max + เคส 1 ชิ้น -> กดยืนยันส่งคลัง
  3. `[STOCK]` ตรวจสอบหน้าจอ เห็นรายการเด้งเข้ามา -> กด `SEARCHING` -> เดินไปหยิบของ -> กด `FOUND` (สต็อกตัด 1 ชิ้น) -> นำส่งแคชเชียร์ กด `SENT_TO_CASHIER`
  4. `[CASHIER]` ตรวจสอบหน้าจอ เห็นรายการเด้งเข้ามา -> กด `CASHIER_RECEIVED` -> กด `CASHIER_SCAN` -> กด `BILL_OPENED` -> กด `COMPLETED`
* **ผลลัพธ์ที่คาดหวัง:**
  - สถานะจบที่ `COMPLETED` อย่างราบรื่น
  - ระบบบันทึกเวลา Server Timestamps ครบทั้ง 11 จุดสมบูรณ์ ไม่มีการกดปุ่มข้ามขั้นตอน

---

### TC-E2E-02: Stock Not Found & Re-selection Cycle (ทดสอบวงรอบสินค้าไม่พบและเจรจาสำเร็จ)
* **เครื่องมือ:** เปิด 3 หน้าต่างพร้อมกัน (`STAFF01`, `STOCK01`, `CASHIER01`)
* **ขั้นตอนการทดสอบ:**
  1. `[STAFF]` สั่งซื้อ iPhone 15 Pro Max 256GB สีน้ำเงิน (สินค้าไม่มีสต็อกจริง)
  2. `[STOCK]` กด `SEARCHING` -> หาไม่พบ -> ติ๊กเลือกชิ้นที่ไม่พบ -> กด `RETURN_TO_STAFF` (บันทึก `stock_not_found_at`, ปรับสต็อกเป็น 0)
  3. `[STAFF]` หน้าจอเด้งแจ้งเตือน -> กด `START_CONSULT` -> ลูกค้าตกลงเปลี่ยนเป็นสี Natural Titanium -> เลือกสีใหม่และกดยืนยัน (บันทึก `re_confirmed_at`, ผลลัพธ์ `CHANGED_ITEM`, รอบค้นหา = 2)
  4. `[STOCK]` เห็นรายการรอบที่ 2 เข้ามา -> กด `SEARCHING` -> หยิบสี Natural Titanium -> กด `FOUND` -> กด `SENT_TO_CASHIER`
  5. `[CASHIER]` รับสินค้า -> สแกน -> เปิดบิล -> กด `COMPLETED`
* **ผลลัพธ์ที่คาดหวัง:**
  - ระบบบันทึกรอบค้นหา `search_cycle_count = 2`
  - มีการบันทึก Timestamp ในช่วง Loop ครบถ้วน (`stock_not_found_at`, `staff_consult_start_at`, `re_confirmed_at`) และปิดงานสำเร็จ

### TC-E2E-03: Cancellation at Cashier & Automatic Stock Restoration (ทดสอบการยกเลิกที่แคชเชียร์และการคืนสต็อก)
* **เครื่องมือ:** เปิด 3 หน้าต่างพร้อมกัน (`STAFF01`, `STOCK01`, `CASHIER01`)
* **ขั้นตอนการทดสอบ:**
  1. ตรวจสอบจำนวนสต็อกเริ่มต้นของ iPhone 15 Pro (สมมติมี 3 เครื่อง)
  2. `[STAFF]` สั่งซื้อ iPhone 15 Pro 1 เครื่อง -> ส่งคลัง
  3. `[STOCK]` กด `SEARCHING` -> กด `FOUND` (สต็อกในระบบลดเหลือ 2 เครื่อง) -> ส่งต่อแคชเชียร์
  4. `[CASHIER]` รับสินค้า -> ลูกค้าปฏิเสธการจ่ายเงินขอยกเลิก -> กดปุ่ม "ยกเลิก" -> ระบุเหตุผล "ลูกค้าเปลี่ยนใจ"
  5. ตรวจสอบจำนวนสต็อกคงเหลือในระบบหลังจากการยกเลิก
* **ผลลัพธ์ที่คาดหวัง:**
  - Session สิ้นสุดด้วยสถานะ `CUSTOMER_CANCELLED`
  - **สต็อก iPhone 15 Pro ในระบบสาขาถูกคืนค่ากลับมาเป็น 3 เครื่องตามเดิมโดยอัตโนมัติ**
