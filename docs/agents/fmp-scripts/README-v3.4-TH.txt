=====================================================================
ses v3.4  (ไฟล์ ses_v3.4.txt) — ทีม SES 2026-11-10 (D123)
=====================================================================
เรื่อง: ออเดอร์ที่ถูกส่งกลับ STOCK (เช่น หยิบผิดรุ่น) หรือถูกยกเลิกใน SES หลังส่งถึงแคชเชียร์แล้ว
เดิม (v3.3): SES ส่งออเดอร์เดิมมาอีกรอบ สคริปต์ตอบ ALREADY_DONE บิลพักเดิมค้างกับ SN ตัวเก่า แคชเชียร์ต้องยกเลิกเอง
ใหม่ (v3.4):
  1) พนักงานกด "ส่งกลับ STOCK" ใน SES -> SES ส่ง event "RETURNED_TO_STOCK" มา
     สคริปต์เอาบิลพักนั้นออก (ลบรายการใน POS_front_sale_detail ของบิล SN ว่างให้สแกนใหม่) ses_status = "RETURNED"
  2) STOCK แก้แล้วส่งใหม่ -> SES ส่ง "revision": 2 และ "revisionNote" (เหตุผล)
     สคริปต์เปิดบิลพักใหม่ตามปกติ หมายเหตุบนบิล (ses_note) เช่น "SES-20261110-000002 · คิว A002 · แก้ไขครั้งที่ 2: หยิบผิดรุ่น"
     ถ้าบิลพักรอบก่อนยังอยู่ (ยังไม่ได้รับ event ข้อ 1) สคริปต์เอาออกให้ก่อน แล้วเปิดใบใหม่
  3) ยกเลิกออเดอร์ใน SES -> SES ส่ง event "CANCELLED" (state = "CANCELLED") สคริปต์เอาบิลพักออก ses_status = "CANCELLED"
     หลังจากนี้ออเดอร์นี้จะไม่ถูกเปิดบิลอีก (ตอบ ORDER_CANCELLED)
  คุณกบไม่ต้องเขียนสคริปต์ยกเลิกฝั่ง SES แยก ใช้สคริปต์ ses ตัวนี้ตัวเดียว

ก่อนวางสคริปต์ ต้องเพิ่ม 2 ฟิลด์
  ses::ses_rev                 Number   รอบล่าสุดที่สคริปต์ทำแล้ว (กันข้อความที่มาช้าทำซ้ำ)
  pos_front_sale_tmp::ses_note Text     หมายเหตุบนบิลพัก
  แล้วรบกวนวาง ses_id, ses_queue, ses_note บนหน้าจอบิลพักของแคชเชียร์ แคชเชียร์จะได้รู้ว่าบิลมาจาก SES คิวไหน แก้มากี่ครั้ง

ตั้งค่า (ข้อ 0. Config)
  $RELEASE_MODE = "delete"  ลบหัวบิล (pos_front_sale_tmp) ทิ้ง
  ถ้า FMP ยกเลิกบิลพักด้วยการเปลี่ยน status ให้ใส่ค่า status นั้นแทน เช่น "cancel" (หัวบิลจะอยู่ แต่ status เปลี่ยน)
  ทั้งสองแบบลบรายการของบิลนั้น เพราะข้อ 3 ตรวจ SN จากรายการ (invStatus ว่าง + mark_tmp = "tmp")

ไม่แตะบิลที่ถูกใช้แล้ว
  ถ้าบิลพัก status ไม่ใช่ "hold" หรือมีรายการที่ออกใบกำกับแล้ว (invStatus ไม่ว่าง) ตอบ BILL_IN_USE ไม่ลบอะไร
  SES จะขึ้นเตือนในแผง "ออเดอร์ที่ต้องดู" ให้แคชเชียร์จัดการเอง

ผลลัพธ์ใหม่ (SES อ่านได้แล้ว ไม่ต้องแก้ฝั่ง SES เพิ่ม)
  RELEASED            เอาบิลพักออกแล้ว (lines = จำนวนรายการที่ลบ)
  NOTHING_TO_RELEASE  ไม่มีบิลพักให้เอาออก (เช่น ยังไม่เคยเปิดได้ หรือถูกยกเลิกใน FMP ไปแล้ว)
  STALE               ข้อความรอบเก่าที่มาช้า ไม่ทำอะไร
  ORDER_CANCELLED     ออเดอร์ยกเลิกแล้ว ไม่เปิดบิล
  BILL_IN_USE         (ok = false) บิลถูกเปิดทำรายการ/ชำระแล้ว ไม่ได้เอาออก
  RELEASE_FAILED      (ok = false) อ่านหรือลบไม่สำเร็จ
  เปิดบิลรอบใหม่ใช้ code เดิม (CREATED / CREATED_SN_LATER) มี "revision" และข้อความนำหน้า "แก้ไขครั้งที่ N (แทนบิลพักเดิม: เหตุผล)"

ช่วงที่ยังใช้ v3.3: SES ส่ง event ใหม่มาแล้วก็ไม่พัง v3.3 ตอบ WRONG_STATE หรือ ALREADY_DONE ตามเดิม (แคชเชียร์ยกเลิกบิลเองเหมือนตอนนี้)

ทดสอบ: ส่งออเดอร์ทดสอบ 1 ใบ -> SES กด "ส่งกลับ STOCK" -> ดูว่าบิลพักหายและ SN ว่าง -> STOCK ส่งใหม่ -> ดูบิลใหม่มีหมายเหตุ "แก้ไขครั้งที่ 2"
