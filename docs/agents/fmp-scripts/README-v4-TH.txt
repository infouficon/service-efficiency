0. ก่อนเริ่ม
---------------------------------------------------------------------
- Export สคริปต์ ses ตัวที่ใช้อยู่เก็บไว้ก่อน (ไว้ย้อนกลับ)
- ถ้าแก้อะไรในตัวจริงเองหลังวาง v3.3 (เช่น จับคู่ PayBy) ให้ย้ายมาใส่ใน v4 ด้วย
  โดยเฉพาะ PayBy: ใส่ในตาราง $PAYBY_MAP ข้อ 0 ของ ses_v4 (ดูข้อ 3)

1. เพิ่มฟิลด์ (ต้องทำก่อนวางสคริปต์ ไม่งั้นสคริปต์จะขึ้น <Field Missing>)
---------------------------------------------------------------------
  ses::ses_rev                   Number   รอบล่าสุดที่สคริปต์ทำแล้ว (กันข้อความที่มาช้าทำซ้ำ)   ** ต้องเพิ่ม
  หมายเหตุ SES เช่น "SES-20261110-000002 · คิว A002 · แก้ไขครั้งที่ 2: หยิบผิดรุ่น" ลงฟิลด์ตาม $NOTE_FIELD (ข้อ 3)
    แนะนำใช้ช่อง Comment บนหน้าจอขายหน้าร้าน (ถ้าติดไปบิลจริงตอนยืนยัน หมายเหตุจะอยู่บนบิลจริงด้วย) = ไม่ต้องเพิ่มฟิลด์
    ถ้าจะแยกฟิลด์: เพิ่ม pos_front_sale_tmp::ses_note (Text) ซึ่งเป็นค่าเริ่มต้นของ $NOTE_FIELD

3. ตั้งค่าในข้อ 0. Config ของ ses_v4
---------------------------------------------------------------------
  $ALLOW_TEST     = 0 บน Production (ปฏิเสธออเดอร์ทดสอบ)
  $NOTE_FIELD     = ชื่อเต็มของฟิลด์ที่ใส่หมายเหตุ SES เช่น "pos_front_sale_tmp::<ช่อง Comment>"
                    ค่าเริ่มต้น "pos_front_sale_tmp::ses_note" (ต้องเพิ่มฟิลด์นี้ถ้าไม่เปลี่ยน)
  $PAYBY_MAP      ตารางจับคู่ "ชื่อช่องทางใน SES=PayBy ใน FMP" บรรทัดละคู่  ** ใหม่ใน v4
                    เติม 5 ตัวที่ตรงกับ PayBy เดิมไว้แล้ว ที่เหลือเว้นหลัง "=" ไว้ให้ทีม FMP เติม:
                    SPayLater, TrueMoney, PayNext, UFund, Ulite, Thisshop, Kashjoy, S Leasing, WEB, 2C2P ( หน้าร้าน ), U-Joy
                    ตัวที่ยังว่างหรือไม่มีในตาราง: PayBy ได้ชื่อเดิมของ SES และ SES ขึ้นเตือน "ยังไม่ได้จับคู่ PayBy: ..."
                    ช่องทางที่ยังไม่มีใน FMP (SPayLater, TrueMoney, PayNext, WEB) เพิ่ม PayBy ใน FMP ก่อน แล้วค่อยเติมในตาราง
                    ถ้า ADMIN ของ SES เพิ่มช่องทางใหม่ ต้องเพิ่มบรรทัดในตารางนี้ด้วย

4. เรียกสคริปต์ที่ไหน
---------------------------------------------------------------------
  ses                 ไม่ต้องเรียกเอง SES เรียกผ่าน Data API ทุกครั้งที่ส่งออเดอร์ / ส่งกลับ STOCK / ยกเลิก
  ses_report_bill     ท้ายสคริปต์ชำระเงิน/ออกใบเสร็จ เฉพาะบิลที่ pos_front_sale_tmp::ses_id ไม่ว่าง
                      param: {"sesID": ses_id, "billNo": <เลขที่บิล>, "paid": 1, "openedAt": ses::processed_at}
  ses_report_cancel   ท้ายสคริปต์ยกเลิกบิลพักของ FMP เฉพาะบิลที่ pos_front_sale_tmp::ses_id ไม่ว่าง
                      param: {"sesID": ses_id, "reason": <เหตุผล>, "paid": 0}
                      ยกเลิกบิลที่ชำระแล้ว: "paid": 1 และ "billNo": <เลขที่บิล>

  คีย์: POS_API_KEY (ses_report_bill) และ FMP_CALLBACK_KEY (ses_report_cancel ตัวเดียวกับที่ยิงทดสอบ 31 ต.ค.)
        อ่านจากฟิลด์ที่จำกัดสิทธิ์ ห้ามเขียนคีย์ลงสคริปต์ตรงๆ


---------------------------------------------------------------------
5. หน้าจอบิลพักของแคชเชียร์
---------------------------------------------------------------------
  แสดง ses_id, ses_queue และหมายเหตุ ($NOTE_FIELD) แคชเชียร์จะรู้ว่าบิลมาจาก SES คิวไหน แก้มากี่ครั้ง เพราะอะไร
  (ถ้าใช้ช่อง Comment ที่อยู่บนหน้าจออยู่แล้ว ไม่ต้องแก้หน้าจอ)


---------------------------------------------------------------------
6. สิ่งที่สคริปต์ ses ทำ (สรุปทั้งหมด)
---------------------------------------------------------------------
  ส่งถึงแคชเชียร์ (SENT_TO_CASHIER)
    ตรวจ SN ทีละเครื่อง -> สร้างร่างบิล pos_front_sale_tmp (status "hold") พร้อมหมายเหตุ SES
    เครื่องที่ SN ไม่อยู่ในสต็อกสาขานี้: ข้าม ไม่ลงบิล ให้แคชเชียร์สแกนขายเพิ่ม (CREATED_SN_LATER)
    ผลตรวจทีละเครื่องส่งกลับใน "snCheck"
  ส่งกลับ STOCK (RETURNED_TO_STOCK)
    ลบร่างบิลและรายการของร่าง (SN ว่าง) ses_status = "RETURNED"
  STOCK ส่งใหม่ ("revision": 2, 3, ...)
    เปิดบิลพักใบใหม่ หมายเหตุ "แก้ไขครั้งที่ N: เหตุผล" (ถ้าบิลรอบก่อนยังอยู่ เอาออกให้ก่อน)
  ยกเลิกออเดอร์ใน SES (CANCELLED)
    เอาบิลพักออก ses_status = "CANCELLED" หลังจากนี้ไม่เปิดบิลให้ออเดอร์นี้อีก
  ไม่แตะบิลที่แคชเชียร์ทำต่อไปแล้ว:
    ร่างหายไปแล้ว (กดยืนยันเป็นบิลจริงใน pos_front_sale แล้ว) -> BILL_CONFIRMED แคชเชียร์ยกเลิกบิลจริงเอง
    ร่าง status ไม่ใช่ "hold" หรือมีรายการออกใบกำกับแล้ว -> BILL_IN_USE


---------------------------------------------------------------------
7. ผลลัพธ์ที่ SES เข้าใจ (ไม่ต้องแก้ฝั่ง SES เพิ่ม)
---------------------------------------------------------------------
  CREATED / CREATED_SN_LATER   เปิดบิลพักแล้ว (มี "revision" ถ้าเป็นรอบแก้ไข ข้อความขึ้นต้น "แก้ไขครั้งที่ N")
  ALREADY_DONE                 ส่งซ้ำรอบเดิม บิลพักเปิดไปแล้ว
  RELEASED                     เอาบิลพักออกแล้ว
  NOTHING_TO_RELEASE           ไม่มีบิลพักให้เอาออก
  STALE                        ข้อความรอบเก่าที่มาช้า ไม่ทำอะไร
  ORDER_CANCELLED              ออเดอร์ยกเลิกแล้ว ไม่เปิดบิล
  BILL_IN_USE      (error)     ร่างถูกเปิดทำรายการอยู่ ไม่ได้เอาออก แคชเชียร์จัดการเอง
  BILL_CONFIRMED   (error)     ร่างหายไปแล้ว (ยืนยันเป็นบิลจริงแล้ว) ไม่ได้เอาออก ต้องยกเลิกบิลจริงใน FMP เอง
  RELEASE_FAILED   (error)     อ่าน/ลบบิลไม่สำเร็จ
  อื่นๆ (error)                 SN ผิดรุ่น / ขายไปแล้ว / ซ้ำ ฯลฯ ตามเดิม


---------------------------------------------------------------------
8. ฝั่ง SES ทำอะไรเพิ่มแล้ว (ไม่ต้องแก้ใน FMP)
---------------------------------------------------------------------
  - ตรวจ SN ตอนสแกน: iPhone / iPad Cellular / Watch Cellular ต้องเป็น IMEI 15 หลักที่เลขตรวจถูก
    (14 หลัก = MEID ไม่รับ) · Mac / iPad Wi-Fi / Watch GPS ต้องเป็น Serial No. ขึ้นต้นด้วยตัวอักษร
  - ออเดอร์ที่ยกเลิกแล้ว ส่งไปเป็น state "CANCELLED" เสมอ กันเปิดบิลผิด


---------------------------------------------------------------------
9. ทดสอบหลังวาง (ส่งผลให้ทีม SES ดูได้เลย)
---------------------------------------------------------------------
  1) SES ส่งออเดอร์ทดสอบ 1 ใบ (2 เครื่อง) -> ร่างบิลขึ้นครบ 2 รายการ, หมายเหตุ SES ถูก, PayBy ตรงตาราง
  2) SES กด "ส่งกลับ STOCK" -> บิลพักหาย, SN ว่าง
  3) STOCK สแกนใหม่แล้วส่ง -> บิลพักใบใหม่ หมายเหตุ "แก้ไขครั้งที่ 2: ..."
  4) ชำระเงิน -> ses_report_bill ส่งเลขบิล SES ปิดการขาย
  5) อีกใบ: ส่งถึงแคชเชียร์แล้วกดยกเลิกใน SES -> บิลพักหาย, ส่งซ้ำแล้วได้ ORDER_CANCELLED

ช่วงที่ยังไม่วาง v4: SES ส่ง event ใหม่ได้โดยไม่พัง สคริปต์เดิมตอบ WRONG_STATE / ALREADY_DONE แคชเชียร์ยกเลิกบิลเองเหมือนเดิม
