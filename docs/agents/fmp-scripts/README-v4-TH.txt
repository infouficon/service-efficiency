=====================================================================
FMP x SES สคริปต์ชุด v4.2 (ล่าสุด 2026-11-11) — คู่มือวางสคริปต์ฉบับเดียวจบ
v4.2 แก้จากการตรวจโค้ด (เปลี่ยนแค่ ses_v4.txt สคริปต์อื่นเหมือน v4.1):
  1) แคชเชียร์ยืนยันเป็นบิลจริงแล้วพนักงานกดส่งกลับ STOCK: v4.1 วนติด BILL_CONFIRMED ทุกรอบ ไม่เคยเปิดร่างใหม่
     v4.2 ดูบิลจริงใน pos_front_sale ตาม ses_id ก่อน (ตั้งค่าในข้อ 3) ไม่วนติดแล้ว
  2) record ses ค้าง PROCESSING (สคริปต์หยุดกลางทาง) เกิน 5 นาที ทำต่อได้ ไม่ค้าง IN_PROGRESS ตลอดไป
  3) ส่งกลับ STOCK / ยกเลิก ระหว่างที่รอบก่อนกำลังเปิดบิล: ตอบ IN_PROGRESS แล้ว SES ส่งซ้ำเอง ไม่ชนกัน
  4) ExecuteSQL error ตอนหาลูกค้า / สาขา / เช็ค SN ขายแล้ว = แจ้ง error กลับ ไม่เปิดบิลแบบลูกค้าใหม่
  5) ชื่อฟิลด์ใน $NOTE_FIELD ผิด = ไม่เปิดบิล พร้อมบอกว่าฟิลด์ไหน (v4.1 เปิดบิลโดยไม่มีหมายเหตุ ไม่มีใครรู้)
  6) บัตร / เดือนผ่อน, ประเภทใบเสร็จ และ VAT Refund ที่พนักงานเลือกใน SES ต่อท้ายหมายเหตุ และลงฟิลด์ FMP ได้ (ข้อ 3)
v4.1 ตามที่คุณกบอธิบาย: pos_front_sale_tmp เป็นแค่ร่าง บิลจริงสร้างใน pos_front_sale ตอนแคชเชียร์กดยืนยัน
  -> เอาร่างออก = ลบทิ้งเสมอ · ร่างหายไปแล้ว (ยืนยันแล้ว) = ไม่แตะ ตอบ BILL_CONFIRMED · หมายเหตุ SES เลือกฟิลด์ได้ ($NOTE_FIELD)

3. ตั้งค่าในข้อ 0. Config ของ ses_v4
---------------------------------------------------------------------
  $ALLOW_TEST     = 0 บน Production (ปฏิเสธออเดอร์ทดสอบ)
  $NOTE_FIELD     = ชื่อเต็มของฟิลด์ที่ใส่หมายเหตุ SES เช่น "pos_front_sale_tmp::<ช่อง Comment>"
                    ค่าเริ่มต้น "pos_front_sale_tmp::ses_note" (ต้องเพิ่มฟิลด์นี้ถ้าไม่เปลี่ยน)
  $PAYBY_MAP      ตารางจับคู่ "ชื่อช่องทางใน SES=PayBy ใน FMP" บรรทัดละคู่  ** ใหม่ใน v4
                    เติม 5 ตัวที่ตรงกับ PayBy เดิมไว้แล้ว ที่เหลือเว้นหลัง "=" ไว้ให้ทีม FMP เติม:
                    SPayLater, TrueMoney, PayNext, UFund, Ulite, Thisshop, Kashjoy, S Leasing, WEB, 2C2P ( หน้าร้าน ), U-Joy
                    ตัวที่ยังว่างหรือไม่มีในตาราง: PayBy ได้ชื่อเดิมของ SES และ SES ขึ้นเตือน "ยังไม่ได้จับคู่ PayBy: ..."
                    ช่องทางที่ยังไม่มีใน FMP (SPayLater, TrueMoney, PayNext, WEB) เพิ่ม PayBy ใน FMP ก่อน แล้วค่อยเติมในตาราง
                    ถ้า ADMIN ของ SES เพิ่มช่องทางใหม่ ต้องเพิ่มบรรทัดในตารางนี้ด้วย
  -- v4.2 --
  $PROCESSING_TIMEOUT_MIN = 5   record ses ค้าง PROCESSING นานกว่านี้ (นาที) = รอบก่อนหยุดกลางทาง ทำต่อได้
  $REAL_BILL_SQL          นับบิลจริงของออเดอร์ "SELECT COUNT(*) FROM pos_front_sale WHERE ses_id = ?"
                          แก้ชื่อตาราง/ฟิลด์ให้ตรงกับไฟล์จริง
  $REAL_BILL_ACTIVE_SQL   นับเฉพาะบิลจริงที่ยังไม่ยกเลิก ** ทีม FMP ต้องเติม เช่น
                          "SELECT COUNT(*) FROM pos_front_sale WHERE ses_id = ? AND \"status\" <> 'cancel'"
                          (ใส่ฟิลด์และค่าที่ FMP ใช้บอกว่าบิลยกเลิกแล้ว)
                          เว้นว่าง = ตรวจไม่ได้: ตอบ BILL_CONFIRMED เตือนแคชเชียร์ แล้วรอบส่งถัดไปเปิดร่างใหม่ (ไม่วนติด
                          แต่ถ้าแคชเชียร์ลืมยกเลิกบิลจริงใบเดิม จะมีบิลสองใบ)
  $RECEIPT_FIELD          ฟิลด์ FMP ที่จะลงประเภทใบเสร็จ เว้นว่าง = ไม่ลง (ยังอยู่ในหมายเหตุ)
  $RECEIPT_MAP            แปลงรหัสของ SES เป็นค่าของ FMP: TAX_CORPORATE=… / TAX_INDIVIDUAL=… / SIMPLIFIED=…
                          เว้นหลัง "=" = ใช้ชื่อภาษาไทยที่ SES ส่งมา (ใบกำกับภาษีในนามนิติบุคคล / ใบกำกับภาษีในนามบุคคล / ใบเสร็จอย่างย่อ)
  $CARD_FIELD             ฟิลด์ FMP ที่จะลงชื่อบัตร เว้นว่าง = ไม่ลง
  $CARD_MAP               แปลงชื่อบัตรของ SES เป็นค่าของ FMP: KBank, SCB, KTC, BBL, Krungsri, TTB, UOB, CardX, First Choice
                          เว้นหลัง "=" = ใช้ชื่อที่ SES ส่งมา · ADMIN ของ SES เพิ่มบัตรใหม่เมื่อไร เพิ่มบรรทัดที่นี่ด้วย
  $INSTALLMENT_FIELD      ฟิลด์ FMP ที่จะลงจำนวนเดือนผ่อน (ตัวเลข) เว้นว่าง = ไม่ลง
  ชื่อฟิลด์ที่ตั้งผิด = สคริปต์ไม่เปิดบิล และบอกชื่อฟิลด์นั้นกลับไปที่ SES (error 5004-5007)

4. เรียกสคริปต์ที่ไหน
---------------------------------------------------------------------
  ses                 ไม่ต้องเรียกเอง SES เรียกผ่าน Data API ทุกครั้งที่ส่งออเดอร์ / ส่งกลับ STOCK / ยกเลิก

                      param: {"sesID": ses_id, "reason": <เหตุผล>, "paid": 0}
                      ยกเลิกบิลที่ชำระแล้ว: "paid": 1 และ "billNo": <เลขที่บิล>

  คีย์: POS_API_KEY (ses_report_bill) และ FMP_CALLBACK_KEY (ses_report_cancel ตัวเดียวกับที่ยิงทดสอบ 31 ต.ค.)
        อ่านจากฟิลด์ที่จำกัดสิทธิ์ ห้ามเขียนคีย์ลงสคริปต์ตรงๆ

6. สิ่งที่สคริปต์ ses ทำ (สรุปทั้งหมด)
---------------------------------------------------------------------
  ส่งถึงแคชเชียร์ (SENT_TO_CASHIER)
    ตรวจ SN ทีละเครื่อง -> สร้างร่างบิล pos_front_sale_tmp (status "hold") พร้อมหมายเหตุ SES
    เครื่องที่ SN ไม่อยู่ในสต็อกสาขานี้: ข้าม ไม่ลงบิล ให้แคชเชียร์สแกนขายเพิ่ม (CREATED_SN_LATER)
    ผลตรวจทีละเครื่องส่งกลับใน "snCheck"
  ส่งกลับ STOCK (RETURNED_TO_STOCK)
    ลบร่างบิลและรายการของร่าง (SN ว่าง) ses_status = "RETURNED"
  STOCK ส่งใหม่ ("revision": 2, 3, ...)
    เปิดบิลพักใบใหม่ หมายเหตุ "แก้ไขครั้งที่ N: เหตุผล" (ถ้าบิลรอบก่อนยังอยู่ เอาออกให้ก่อน)
  ยกเลิกออเดอร์ใน SES (CANCELLED)
    เอาบิลพักออก ses_status = "CANCELLED" หลังจากนี้ไม่เปิดบิลให้ออเดอร์นี้อีก
  ไม่แตะบิลที่แคชเชียร์ทำต่อไปแล้ว:
    ร่างหายไปแล้ว (กดยืนยันเป็นบิลจริงใน pos_front_sale แล้ว) v4.2 ดูบิลจริงตาม ses_id:
      บิลจริงยังไม่ยกเลิก -> BILL_CONFIRMED ไม่เปิดร่างใหม่ (กันบิลซ้ำ) แคชเชียร์ยกเลิกบิลจริงแล้ว STOCK ส่งใหม่ได้
      บิลจริงยกเลิกแล้ว   -> ทำต่อปกติ (ส่งกลับ STOCK = NOTHING_TO_RELEASE · ส่งรอบใหม่ = เปิดร่างใหม่)
      ตรวจไม่ได้          -> BILL_CONFIRMED เตือนแคชเชียร์ และรอบส่งถัดไปเปิดร่างใหม่ได้
    ร่าง status ไม่ใช่ "hold" หรือมีรายการออกใบกำกับแล้ว -> BILL_IN_USE

7. ผลลัพธ์ที่ SES เข้าใจ (ไม่ต้องแก้ฝั่ง SES เพิ่ม)
---------------------------------------------------------------------
  CREATED / CREATED_SN_LATER   เปิดบิลพักแล้ว (มี "revision" ถ้าเป็นรอบแก้ไข ข้อความขึ้นต้น "แก้ไขครั้งที่ N")
  ALREADY_DONE                 ส่งซ้ำรอบเดิม บิลพักเปิดไปแล้ว
  RELEASED                     เอาบิลพักออกแล้ว
  NOTHING_TO_RELEASE           ไม่มีบิลพักให้เอาออก
  STALE                        ข้อความรอบเก่าที่มาช้า หรือระหว่างเตรียมบิลออเดอร์ถูกส่งกลับ / ยกเลิกไปแล้ว ไม่ทำอะไร
  IN_PROGRESS      (รอ)        อีกสคริปต์กำลังเปิดบิลของออเดอร์นี้อยู่ SES ส่งข้อความเดิมซ้ำเองใน 1-5 นาที
  ORDER_CANCELLED              ออเดอร์ยกเลิกแล้ว ไม่เปิดบิล
  BILL_IN_USE      (error)     ร่างถูกเปิดทำรายการอยู่ ไม่ได้เอาออก แคชเชียร์จัดการเอง
  BILL_CONFIRMED   (error)     ร่างหายไปแล้ว (ยืนยันเป็นบิลจริงแล้ว) ไม่ได้เอาออก ต้องยกเลิกบิลจริงใน FMP เอง
                               มี "realBill": ACTIVE (บิลจริงยังอยู่) / UNKNOWN (ตรวจไม่ได้)
  RELEASE_FAILED   (error)     อ่าน/ลบบิลไม่สำเร็จ
  QUERY_FAILED     (error)     ExecuteSQL หาลูกค้า / สาขาไม่สำเร็จ ไม่ได้เปิดบิล (ADMIN กดส่งซ้ำได้)
  SN_CHECK_ERROR   (error)     ExecuteSQL ตรวจ SN ไม่สำเร็จ
  อื่นๆ (error)                 SN ผิดรุ่น / ขายไปแล้ว / ซ้ำ ฯลฯ ตามเดิม

8. ฝั่ง SES ทำอะไรเพิ่มแล้ว (ไม่ต้องแก้ใน FMP)
---------------------------------------------------------------------
  - ตรวจ SN ตอนสแกน: iPhone / iPad Cellular / Watch Cellular ต้องเป็น IMEI 15 หลักที่เลขตรวจถูก
    (14 หลัก = MEID ไม่รับ) · Mac / iPad Wi-Fi / Watch GPS ต้องเป็น Serial No. ขึ้นต้นด้วยตัวอักษร
  - ออเดอร์ที่ยกเลิกแล้ว ส่งไปเป็น state "CANCELLED" เสมอ กันเปิดบิลผิด
  - v4.2 ข้อมูลใหม่ในข้อความที่ส่งมา (อยู่ใน ses_body):
      "paymentDetails": [{"method": "0% Credit Card", "type": "บัตรเงินผ่อน", "cardType": "SCB", "installmentMonths": 10,
                          "label": "0% Credit Card (SCB 10 เดือน)"}]   ช่องทางที่ไม่มีบัตร cardType / installmentMonths = null
      "receiptType": "TAX_CORPORATE" | "TAX_INDIVIDUAL" | "SIMPLIFIED" | null
      "receiptTypeLabel": "ใบกำกับภาษีในนามนิติบุคคล" | "ใบกำกับภาษีในนามบุคคล" | "ใบเสร็จอย่างย่อ" | null
      "vatRefund": true/false · "taxInvoice": true/false (เดิม)
  - SES ไม่ให้ยืนยันออเดอร์ที่จ่ายด้วยบัตรเครดิตโดยไม่เลือกบัตร (0% ต้องเลือกเดือนผ่อนด้วย) ตรวจทั้งหน้าจอและ server
  - ได้ IN_PROGRESS จากสคริปต์ = SES ส่งข้อความเดิมซ้ำเองตามรอบ (1, 2, 5 นาที …)

9. ทดสอบหลังวาง (ส่งผลให้ทีม SES ดูได้เลย)
---------------------------------------------------------------------
  1) SES ส่งออเดอร์ทดสอบ 1 ใบ (2 เครื่อง) -> ร่างบิลขึ้นครบ 2 รายการ, หมายเหตุ SES ถูก, PayBy ตรงตาราง
  2) SES กด "ส่งกลับ STOCK" -> บิลพักหาย, SN ว่าง
  3) STOCK สแกนใหม่แล้วส่ง -> บิลพักใบใหม่ หมายเหตุ "แก้ไขครั้งที่ 2: ..."
  4) ชำระเงิน -> ses_report_bill ส่งเลขบิล SES ปิดการขาย
  5) อีกใบ: ส่งถึงแคชเชียร์แล้วกดยกเลิกใน SES -> บิลพักหาย, ส่งซ้ำแล้วได้ ORDER_CANCELLED
  6) v4.2 อีกใบ: แคชเชียร์กดยืนยันเป็นบิลจริง แล้ว SES กด "ส่งกลับ STOCK" -> BILL_CONFIRMED (บิลจริงยังอยู่)
     แคชเชียร์ยกเลิกบิลจริง แล้ว STOCK ส่งใหม่ -> เปิดร่างใบใหม่ "แก้ไขครั้งที่ 2"
